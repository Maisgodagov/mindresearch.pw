Статистический анализ: первая закрытая версия для проверки, 19.10.2026.

## Интерфейс и границы

Режим Operate: расширение действующего кабинета, светлые поверхности, существующие зелёные акценты и компоненты. Список выборок, редактор состава и последовательный расчёт вместо набора разрозненных калькуляторов. Навигация: выборки → новый расчёт → история. На desktop рядом с настройками находится краткая сводка правил; на телефоне всё идёт последовательно. Исходные значения и промежуточные таблицы раскрываются по запросу.

Пилот доступен только системным ролям `owner` и `admin`, проверяется текущая роль в БД, а не только JWT или кнопка. Создание/изменение требует также права автора/редактора на конкретный опрос; административный просмотр чужого опроса остаётся только чтением.

Реализованы 13 методов: описательная статистика, Шапиро—Уилк, одновыборочный/парный t Стьюдента, независимый t Уэлча, Манна—Уитни, Краскала—Уоллиса, независимый однофакторный ANOVA, Вилкоксон, знаки, Пирсон, Спирмен, Кендалл τ-b. Каждый запуск — одна двусторонняя гипотеза с видимым α. Перестановочные варианты, post-hoc, поправки для пакета гипотез, многомерные модели и проверка различий эффектов пока не реализованы. Сопоставление до четырёх готовых отчётов не является тестом различий эффектов.

Группы сохраняются по всем страницам. Состав фиксируется, условия сохраняются отдельно от ручного списка. Новые подходящие участники предлагаются кандидатами. Редактирование состава/названия создаёт новую версию; предыдущие версии и снимки отчётов не перезаписываются. Удалённые прохождения не участвуют в новых расчётах. Дополнение пропусков вручную требует источника и не меняет ответы.

## Движок и эксплуатация

Выбран отдельный процесс Python/SciPy для первой версии: необходимые базовые процедуры проверены на нём. Это уточнение предварительной рекомендации R из общего плана; второй production-runtime сейчас не добавляется. Версии зафиксированы в `apps/api/statistics/requirements.txt`, а фактические Python/NumPy/SciPy сохраняются в отчёте.

Локально создать изолированную Python-среду, установить requirements, задать `STATISTICS_PYTHON` абсолютным путём к её интерпретатору. Production использует системный `python3`, библиотеки устанавливаются в отдельный `/opt/mindresearch/statistics-python` через `python3 -m pip install --target ... -r requirements.txt`. Можно переопределить `STATISTICS_SITE_PACKAGES`. Не обновлять глобальное Python-окружение сервера.

Скрипт `apps/api/statistics/engine.py` — часть исходного релиза; TypeScript-сборка не копирует Python, поэтому release archive должен включать отслеживаемые исходники, как текущий deploy. Новые таблицы создаются аддитивной миграцией при старте. Изменение существующих ответов/методик и seed не нужны.

Очередь сохраняется в MySQL, один процесс расчёта за раз, до 30 секунд на задачу, один поток BLAS. После перезапуска прерванная задача помечается неуспешной; ожидающие продолжаются. Пилот ограничен 5000 участниками опроса, 8 входами и 20 000 значениями на расчёт. Превью проверяет группы, версии, пропуски и контрольную сумму; изменения входов требуют повторного просмотра. Повторная отправка одного requestId не создаёт вторую запись.

Исходные снимки приватны: доступны через тот же серверный доступ к опросу. Удаление самого опроса каскадно удаляет его выборки и отчёты. Политика удаления данных при будущих новых endpoint окончательного удаления прохождений должна учитывать снимки; сейчас прохождения перемещаются в корзину, и старые отчёты сохраняют исторические значения.

## Проверки

`npm run test -w @opora/api` и `npm run test -w @opora/web`.

`python -m unittest discover -s apps/api/statistics -p test_engine.py -v` в зафиксированном окружении.

Численный эталон U: пример из официальной документации SciPy, U₁=17, двусторонний p=1/9. Также проверяются ручные t/дисперсия/биномиальные вероятности, направление эффекта, нулевые значения, совпадения и ошибки вырожденных данных. HTTP-проверки покрывают отсутствие авторизации, запрет researcher на всех маршрутах, чтение admin/owner, запрет чужой записи, сохранение серверной выборки, конфликт версий, снимок/previewHash и происхождение ручных значений.

Для UI использовать синтетические подставные API, не production-прохождения. Основной путь: сохранить → открыть состав/кандидатов → изменить версию → выбрать показатели → проверить значения → рассчитать → открыть формулу/входы → скачать Excel → сопоставить отчёты. Проверить desktop/mobile, пустые состояния, researcher и режим просмотра.
