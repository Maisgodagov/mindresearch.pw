# Аналитика посетителей и согласие

Аналитика включается только после явного разрешения. Короткое уведомление с кнопками «Разрешить» и «Отказаться» показывается, пока выбор не сделан. Выбор хранится 180 дней в cookie `mindresearch_analytics_consent`; localStorage уведомляет другие вкладки об изменении выбора. Постоянной кнопки Cookies нет. Отказ очищает очереди, останавливает запись интерфейса и удаляет HttpOnly cookie гостевого идентификатора через `/api/analytics/forget`. Ранее собранная история не удаляется при отказе и истекает по срокам хранения.

Необходимые cookies авторизации и прохождения тестов продолжают работать независимо от аналитики. Приложение не обещает, что баннер сам по себе решает все юридические вопросы обработки данных.

Гостевые события собираются только с лендинга, каталога, страниц тестов и их прохождения/результата, входа и регистрации. Ссылки исследовательских опросов `/s/...`, профили `/p/...`, приглашения и административные страницы не входят в гостевую аналитику. URL-параметры, ID личного результата, поля ввода, варианты ответов и баллы не передаются. Гостевые записи экранов отсутствуют. Зарегистрированные посетители публичных страниц определяются сервером по авторизации, а не по присланному userId.

Гостевой идентификатор: случайный UUID с HMAC-подписью в HttpOnly cookie сроком 90 дней, только после согласия. IP не сохраняется в событиях: кратковременный хеш в памяти ограничивает частоту запросов. Идентификатор браузера — не человек: разные браузеры, удаление cookies или гостевой визит перед входом могут дать отдельные записи. Гость не сопоставляется задним числом с аккаунтом. Количество отказавшихся не собирается, поэтому отчёт не измеряет всех посетителей сайта.

Для кабинета сохраняется прежний сбор событий и маскированных rrweb-записей, теперь также с проверкой согласия в браузере и на API. События хранятся до 90 дней, записи — до 14 дней. Экран результатов исследований исключён из записи.

Админ-отчёт поддерживает аудитории «Все», «Зарегистрированные», «Гости» и периоды «Сегодня», «Вчера», «24 часа», 7/30/90 дней. Сегодня/вчера — календарные дни UTC+3. 24 часа и 7/30/90 дней — скользящие периоды. Время отбора считается по приёму события сервером, а не по произвольным часам клиента. Часовые/суточные интервалы без событий заполняются нулями. Просмотр доступен admin/owner; персональный отчёт пользователя исключает гостей.

Миграция при старте API добавляет nullable `visitor_id` и индекс в `product_events`, а `user_id` делает nullable с сохранением внешнего ключа. Старые события сохраняются. До публикации обновлённого API/фронта на production гостевой сбор и новые фильтры там не работают; старый API не знает эти поля и маршруты. По этой причине нельзя выкатывать только frontend.

Проверки: `npm run test -w @opora/api -- src/admin-management.test.ts`; полный build API и web; браузерная проверка разрешения, отказа, сохранения выбора после перезагрузки, гостевого отчёта и мобильного баннера на подставных API.
