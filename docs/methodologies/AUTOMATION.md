# Фоновая обработка очереди методик

Runner берёт первую запись `queued` из [`links/_backlog.md`](links/_backlog.md). Он держит две линии: основной Codex CLI последовательно проверяет, реализует и интегрирует текущую методику в основном checkout; отдельный read-only Codex CLI заранее исследует следующую методику в изолированной git worktree-копии. Предварительная записка передаётся основному агенту, который быстро сверяет ключевые утверждения и выполняет реализацию. В общую очередь и файлы проекта в каждый момент пишет только основной агент. Лимит — две попытки и 30 минут на одну попытку. Методика не исключается из-за отсутствия российской апробации, норм, данных о лицензии или независимой копии: единственные методические основания для отказа — ненадёжный/отсутствующий ключ либо отсутствие пригодного русского текста.

Подтверждённые методики коммитятся и отправляются в `main` со статусом `implemented-local`. Runner ждёт GitHub Actions workflow и проверяет production health. Если хостинг, БД или health-check недоступны, методики остаются в накопленном пакете, очередь продолжает работу, а после следующего пункта runner запускает повторный deploy пакета. После успешного workflow и health-check он переводит все накопленные записи в `done`. Ошибки локальных тестов/сборки, отсутствие commit/push и необходимость решения пользователя приостанавливают очередь. `blocked`, `ru-ineligible` и `already-available` не входят в deploy-пакет.

## Управление

Из корня проекта:

```powershell
.\scripts\start-methodology-backlog.ps1
.\scripts\status-methodology-backlog.ps1
.\scripts\stop-methodology-backlog.ps1
```

Для ограниченного запуска: `-MaxItems 10`. Предварительный просмотр: ` .\scripts\run-methodology-backlog.ps1 -DryRun`.

Состояние, транскрипты, логи, исследовательская записка и изолированная worktree-копия хранятся в `%LOCALAPPDATA%\OporaMethodologyRunner`. Lock предотвращает запуск нескольких runner одновременно. Ошибка CLI, остановка или блокер оставляют текущую запись в очереди. Задача Планировщика возобновляет проход ежедневно в 04:00, пока пользователь вошёл в Windows. По завершении очереди расписание удаляется.

Запись с `implemented-local` уже исследована и реализована, но ждёт общего deploy. `done` ставится только после успешного workflow и production health-check. Следующая методика обрабатывается, пока пакет ожидает восстановления deploy.
