# Фоновая обработка очереди методик

До трёх worker-слотов одновременно готовят отдельные методики в изолированных git worktree (`research-worktree-1`, `research-worktree-2`, ...). Каждый создаёт только свой регистрационный модуль и review. Runner последовательно переносит их в основной checkout и коммитит по одному пункту; `seed.ts` не редактируется при каждом добавлении, реестр модулей загружается динамически. Число слотов задаётся `-ResearchSlots` (1–6; по умолчанию 3). Результаты сохраняются по ID в `%LOCALAPPDATA%\OporaMethodologyRunner\research` и используются после перезапуска.

Runner берёт первую доступную запись `queued` из [`links/_backlog.md`](links/_backlog.md) и одновременно запускает до трёх независимых worker-слотов. Каждый слот проверяет русскую версию и ключ, реализует только свою методику и оставляет review. Координатор последовательно принимает проверенные файлы, обновляет backlog и создаёт локальный commit. После двух технических ошибок пункт откладывается на 15 минут, и обработка очереди продолжается. Методика не исключается из-за отсутствия российской апробации, норм, данных о лицензии или независимой копии: основания для отказа — ненадёжный/отсутствующий ключ либо отсутствие пригодного русского текста.

Подтверждённые методики локально коммитятся со статусом `implemented-local`, без push на каждую запись. Runner отправляет пакет после каждых 10 добавленных методик; остаток отправляется, когда очередь исчерпана. Он ждёт GitHub Actions workflow и проверяет production health. Если хостинг, БД или health-check недоступны, методики остаются в накопленном пакете, очередь продолжает работу, а следующая партия повторно включает их в deploy. После успешного workflow и health-check статусы пакета меняются на `done`. Ошибка сборки CI приостанавливает очередь. `blocked`, `ru-ineligible` и `already-available` не входят в deploy-пакет.

## Управление

Из корня проекта:

```powershell
.\scripts\start-methodology-backlog.ps1
.\scripts\status-methodology-backlog.ps1
.\scripts\stop-methodology-backlog.ps1
```

Для ограниченного запуска: `-MaxItems 10`. Предварительный просмотр: ` .\scripts\run-methodology-backlog.ps1 -DryRun`.

Состояние, артефакты, логи и изолированные worktree-копии хранятся в `%LOCALAPPDATA%\OporaMethodologyRunner`. Lock предотвращает запуск нескольких runner одновременно. Ошибка CLI и остановка оставляют текущую запись в очереди; после двух ошибок она откладывается и позже повторяется. Задача Планировщика возобновляет проход ежедневно в 04:00, пока пользователь вошёл в Windows. По завершении очереди расписание удаляется.

Запись с `implemented-local` уже исследована и реализована, но ждёт общего deploy. `done` ставится только после успешного workflow и production health-check. Следующая методика обрабатывается, пока пакет ожидает восстановления deploy.
