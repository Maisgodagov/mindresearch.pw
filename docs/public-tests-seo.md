# Поиск и публичные тесты mindresearch

Дополнение от 02.11.2026: [аудит, карта запросов и действия владельца](seo-audit-2026-11-02.md). Общая SPA-оболочка закрыта `noindex`; при проверке новой публикации обязательно убеждайтесь, что серверный HTML заменил её на `index,follow` и содержит ровно один robots. Canonical лендинга: `https://mindresearch.pro/for-researchers/`. HTTP 404 неизвестных URL требует установки соответствующего Nginx location на production; один клиентский экран ошибки этого не обеспечивает.

## Что настроено

Публичный каталог и статьи имеют единые title/description/canonical, Open Graph и Twitter metadata, отдельные изображения 1200×630. JSON-LD описывает сайт, каталог, список тестов, хлебные крошки и первоисточники статьи. Фальшивые рейтинги/диагностические обещания не используются.

Канонические адреса заканчиваются `/`: `https://mindresearch.pro/methods/` и `/methods/<slug>/`. Такая форма соответствует фактической выдаче каталогов Nginx. Ссылки между статьями, каталогом, canonical и sitemap согласованы. Параметры фильтрации не становятся отдельными целевыми страницами.

Production API перед открытием порта генерирует HTML из опубликованных записей БД. Это позволяет существующему Nginx отдать статью с источниками без JavaScript и без изменения его привилегированной конфигурации. При publish/unpublish HTML и sitemap обновляются; draft на них не влияет. Файлы подменяются атомарно, операции сериализованы.

Результаты и прохождение имеют исходный noindex, не входят в sitemap. Robots.txt не мешает роботу прочитать этот noindex. Доступ к личным данным отдельно защищён cookie — SEO-директивы не заменяют авторизацию.

`/sitemap.xml` и `/methods-sitemap.xml` формируются автоматически по опубликованным статьям. Lastmod — дата фактической публикации, не текущий день при каждом билде. Никаких ручных списков новых slug в sitemap после подключения теста не требуется.

## Как добавлять следующий тест

Используйте `$mindresearch-public-tests`. Исходник скилла: `.agents/skills/mindresearch-public-tests/SKILL.md`. Он установлен также в пользовательский каталог Codex. Скилл охватывает права, авторов, версию бланка, scorer, статью, анонимное прохождение, результаты, PNG, SEO и приёмку.

Редактор публикаций поддерживает необязательные поля «Заголовок для поиска» и «Описание для поиска». Они полезны, если научное название слишком длинное для понятного сниппета. Без них формируется осмысленный вариант из названия и intro. Изменение исходного JSON не затирает существующую публикацию в БД: существующие материалы правятся и публикуются через редактор.

После добавления slug выполните `scripts/generate-public-test-images.cjs` с установленным Playwright. Новые PNG включаются в коммит. Изображения не содержат персональных ответов или результатов посетителей.

## Действия владельца после запуска

1. Подтвердить домен mindresearch.pro в Google Search Console и Яндекс Вебмастере. Предпочтителен DNS-способ, если есть доступ к DNS. Не добавлять случайные verification tokens в код.
2. В обоих кабинетах отправить `https://mindresearch.pro/sitemap.xml`.
3. Проверить URL каталога и трёх статей; увидеть, что робот получает содержательный HTML, canonical правильный, индексирование разрешено. Запросить индексирование нескольких важных новых страниц.
4. После новых публикаций достаточно обновлённого sitemap; вручную можно запросить переобход при важных изменениях. Не ожидать мгновенного появления в выдаче.
5. Смотреть запросы, показы, клики, CTR и исключённые страницы. Уточнять title/description по реальному намерению запроса, а не просто наращивать количество ключевых слов.
6. Добавлять тесты по готовности точной статьи и расчёта. Полезны тематические подборки и ссылки на близкие тесты; сотни практически одинаковых страниц и покупные спам-ссылки не нужны.
7. Обновлять источники и дату редакционной проверки только после реальной проверки. Если у статьи есть эксперт-рецензент, указывать его только с реальными данными и подтверждённым участием.

## Что нельзя обещать

Техническая настройка делает раздел доступным для поиска, но не гарантирует индексацию, сроки или место в выдаче. На это влияют полезность и достоверность страниц, конкуренция и сигналы доверия. Внешние кабинеты нельзя считать подключёнными, пока владелец не подтвердил домен.

## Серверное ограничение и готовая конфигурация

У deploy нет прав изменять действующий `/etc/nginx/sites-available/mindresearch`, поэтому он не перезаписывается автоматически. Публичные статьи уже получают настоящий HTML через файловую выдачу. Однако неизвестный `/methods/<несуществующий-slug>/` может вернуть SPA-оболочку с HTTP200, затем приложение покажет ошибку и noindex. Для настоящего HTTP404 и полностью динамической HTML-выдачи оператор с правами Nginx может перенести блок `location ~ ^/methods...` из `deploy/nginx.conf` в существующий TLS-vhost, выполнить `nginx -t` и reload. Нельзя заменять рабочий TLS-конфиг шаблоном целиком или менять другие сайты на сервере.

Рекомендуемый блок внутри существующего server для mindresearch.pro:

```nginx
location ~ ^/methods(?:/[^/]+)?/?$ {
    proxy_pass http://127.0.0.1:4000;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

После применения проверить неизвестный slug (404), существующий (200), noindex снятой публикации и сохранение корневого поведения для гостя/авторизованного пользователя. При проксировании следует также настроить 301 на каноническую форму URL: этот редирект реализован в API. Файловый экспорт остаётся полезным запасным путём и обеспечивает noindex личных страниц до выполнения JS.
