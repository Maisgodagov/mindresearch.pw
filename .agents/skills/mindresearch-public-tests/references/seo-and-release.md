# SEO и публикация

## Контракт страницы

Канонические адреса тестов — `https://mindresearch.pro/methods/` и `/methods/<slug>/`, с завершающим `/`. Действующий Nginx для физических каталогов переводит URL без слеша на адрес со слешем. Внутренние ссылки, canonical, og:url, JSON-LD и sitemap должны указывать именно итоговый 200 URL, без query/hash/localhost/старого домена `.pw`.

Общие источники SEO: `apps/api/src/public-methods/seo.ts` → HTML в `render.ts` и React `Metadata` в `shared.tsx`. Не добавляй противоречащие теги вручную. Первая загрузка HTML должна содержать уникальные title/description/canonical, H1, описание, научное название, авторов/версию, источники и обычные ссылки. Бот не должен ждать API/JavaScript, чтобы понять тему.

Техническая публикация:

- `createPublicPagesSync` на старте production формирует HTML в `apps/web/dist/methods/` из **published БД**, не из draft.
- После publish/unpublish тот же механизм обновляет страницы, связанные ссылки и sitemap. Файлы заменяются через rename, вызовы сериализованы.
- Не заменяй это экспортом всего `catalog.json`: так можно случайно публиковать черновики и отменять снятие статьи с публикации.
- Новый slug должен попасть в исходный разрешённый каталог и существовать в публикациях. Старые URL не переименовывать без редиректа.
- `sitemap.xml`/`methods-sitemap.xml` создаются автоматически; перечислять новый тест вручную в статическом XML недостаточно. Включаются каталог и опубликованные статьи; исключаются результаты, прохождение, поиск/фильтры и редактор.
- `lastmod` берётся только из реального published_at, а не из времени каждого билда. Не выдумывай даты рецензирования.

## Текст и сниппеты

Для каждого теста подбери один основной намеренный запрос и естественные варианты: «тест самооценки Розенберга», «шкала общей самоэффективности», «MSPSS социальная поддержка». Они должны встречаться там, где помогают читателю. Не создавай клоны страницы под каждое написание.

Title: понятное название + «тест/пройти онлайн» + бренд; достаточно компактно для чтения. Description: что измеряет, как проходит и какой результат получает человек. У Google нет обязательной магической длины, количества ключей или числа слов. Поисковик может изменить сниппет.

На видимой странице: объяснить цель и ограничения; авторов/адаптацию не скрывать; ссылки на первоисточники кликабельны; соседние релевантные тесты и каталог доступны обычными `<a>`. Общий `relatedMethods` выбирает до трёх ссылок, отдавая приоритет той же теме; не выводить все сотни тестов в каждой статье. При существенном росте каталога отдельно продумать индексируемые тематические страницы/пагинацию, не превращая каждый поисковый фильтр в SEO-страницу. Существующие SSR/React статьи не должны расходиться по смыслу. Для тем депрессии/тревоги особенно важно не обещать медицинскую диагностику, если инструмент её не обеспечивает, и проверять актуальные первичные рекомендации.

## Превью и разметка

- Генератор OG: `scripts/generate-public-test-images.cjs`. Выполни при добавлении slug; нужны реальные PNG 1200×630 в `apps/web/public/images/tests/`. Они содержат название теста/бренд, не персональный результат.
- Open Graph: title, description, url, image/alt/width/height, locale; Twitter summary_large_image. Проверить доступность изображения по HTTPS и корректный MIME.
- JSON-LD: WebSite/Organization, CollectionPage + ItemList для каталога; WebPage, BreadcrumbList и citations для статьи. Разметка описывает реально видимое содержимое.
- Не добавляй вымышленные рейтинги, отзывы, author/expert qualifications, FAQ, HowTo или MedicalTest ради расширенного сниппета. Наличие Schema.org не гарантирует специальное отображение.

## Индексация и приватность

`robots.txt` в корне уже существует. Разрешены CSS/JS/шрифты/OG-изображения и публичные статьи. Прохождение и результат получают `noindex,nofollow` в исходном HTML и метаданных React; личный API также no-store/noindex. Не закрывай эти HTML URL в robots.txt так, чтобы робот не мог прочитать noindex. Конфиденциальность обеспечивает cookie-проверка на сервере, а не robots.

Фильтры `q`/`topic`: canonical на каталог, клиентский noindex,follow. Не добавлять фильтры/UTM в sitemap и внутренние SEO-ссылки. Ошибки загрузки/неизвестные статьи не должны наследовать indexable метаданные другого теста. При статической выдаче неизвестный URL может получить оболочку с 200 и JS-noindex; для настоящего HTTP404 и динамической выдачи предусмотрен API-маршрут и пример `deploy/nginx.conf`, который применяет оператор с правами на Nginx. Не утверждай, что это решено, не проверив публичный HTTP-ответ.

## Приёмка и рекомендации владельцу

1. `curl -L https://mindresearch.pro/methods/<slug>/`: уникальные теги и содержательный HTML до JavaScript; ровно один canonical и H1, корректный JSON.
2. Проверить каталог/страницы с выключенным JS; OG PNG должен отвечать 200 image/png.
3. `robots.txt` и `sitemap.xml`: 200, XML без непубличных URL, каждый loc открывается 200 без редиректа; после unpublish статья исчезает из sitemap и получает noindex.
4. Браузер с JS: теги не дублируются/не становятся от другой статьи после переходов; личные результаты остаются noindex и не появляются в sitemap.
5. Google Search Console и Яндекс Вебмастер: подтвердить собственность, отправить sitemap, проверить URL и запросить переобход отдельных важных страниц. Это внешние аккаунты: без доступа владельца не заявлять, что сайт туда добавлен.
6. После запуска смотреть индексирование и реальные запросы/показы/CTR, проверять причины исключения страниц; обновлять статьи по источникам и добавлять релевантные ссылки/подборки.
7. Не закупать спам-ссылки и не выпускать сотни шаблонных тонких страниц только ради объёма. Публиковать по мере готовности полезного, проверенного материала.
